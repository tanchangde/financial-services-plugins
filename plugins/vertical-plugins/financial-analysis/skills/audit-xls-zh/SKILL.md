# 电子表格审计

审计公式与数据的准确性和常见错误。范围决定深度 —— 从选定区域的快速公式检查，一直到完整的财务模型完整性审计。

## 第一步：确定范围

如果用户已经给出了范围，直接采用。否则**询问用户**：

> 您希望我审计哪个范围？
> - **selection** —— 仅当前选中的区域
> - **sheet** —— 仅当前活动工作表
> - **model** —— 整个工作簿，包含财务模型完整性检查（资产负债表平衡、现金勾稽、滚动结转、逻辑合理性）

**model** 范围最深 —— 用于 DCF、LBO、三表模型、并购模型、可比公司模型，或任何在发送给客户或投委会之前的一体化财务模型。

---

## 第二步：公式层检查（所有范围）

无论范围如何，都要执行以下检查：

| 检查项 | 关注点 |
|---|---|
| 公式错误 | `#REF!`、`#VALUE!`、`#N/A`、`#DIV/0!`、`#NAME?` |
| 公式内硬编码 | `=A1*1.05` —— 这里的 `1.05` 应当是单元格引用 |
| 公式不一致 | 某行/列中打破相邻公式模式的公式 |
| 区间差一 | `SUM`/`AVERAGE` 漏掉了首行或末行 |
| 被粘贴覆盖的公式 | 看起来像公式、实际是硬编码数值的单元格 |
| 循环引用 | 有意的或无意的 |
| 跨表链接断裂 | 引用了已移动或被删除的单元格 |
| 单位/量级不匹配 | 千与百万混用、百分比存成整数 |
| 隐藏行/工作表 | 可能藏有覆盖值或过期计算 |

---

## 第三步：模型完整性检查（仅 model 范围）

若范围为 **model**，先识别模型类型（DCF / LBO / 三表 / 并购 / 可比公司 / 自定义），再执行对应的完整性检查。

### 3a. 结构审查

| 检查项 | 关注点 |
|---|---|
| 输入/公式分离 | 输入是否与计算清晰分离？ |
| 颜色约定 | 蓝色=输入、黑色=公式、绿色=链接 —— 或模型自身的约定，是否统一执行？ |
| 工作表流向 | 顺序是否合乎逻辑（假设 → 利润表 → 资产负债表 → 现金流量表 → 估值）？ |
| 日期表头 | 所有工作表是否一致？ |
| 单位 | 是否统一（千、百万还是实际值）？ |

### 3b. 资产负债表

| 检查项 | 测试 |
|---|---|
| 资产负债平衡 | 总资产 = 总负债 + 所有者权益（每一期） |
| 留存收益滚动 | 期初留存收益 + 净利润 − 股利 = 期末留存收益 |
| 商誉/无形资产 | 是否源自并购假设（如有并购） |

如果资产负债表不平，**逐期量化差额并追踪断点在何处** —— 在这一项修好之前，其他都不重要。

### 3c. 现金流量表

| 检查项 | 测试 |
|---|---|
| 现金勾稽 | 现金流量表期末现金 = 资产负债表现金（每一期） |
| 现金流量表合计 | CFO + CFI + CFF = 现金变动 |
| 折旧摊销一致 | 现金流量表的 D&A = 利润表的 D&A |
| 资本开支一致 | 现金流量表的 CapEx 与资产负债表 PP&E 滚动一致 |
| 营运资本变动 | 符号与资产负债表变动一致（ΔAR、ΔAP、Δ存货） |

### 3d. 利润表

| 检查项 | 测试 |
|---|---|
| 收入构建 | 与分部/产品明细勾稽 |
| 税费 | 所得税费用 = 税前利润 × 税率（允许递延税调整） |
| 股数 | 与摊薄计划一致（期权、可转债、回购） |

### 3e. 循环引用

- 利息 → 债务余额 → 现金 → 利息 是 LBO/三表模型中常见的**有意**循环
- 若为有意：确认存在迭代开关且工作正常
- 若为无意：追踪该循环并指出如何打破

### 3f. 逻辑与合理性

| 检查项 | 触发标记的条件 |
|---|---|
| 增长率 | 收入增长 >100% 且无解释 |
| 利润率 | 超出行业常态 |
| 终值占比过大 | 终值 > DCF 企业价值约 75%（黄灯） |
| 曲棍球杆 | 预测期后段不切实际地陡增 |
| 复利效应 | EBITDA 到第 10 年复利成荒谬的数字 |
| 边界情形 | 模型在 0% 或负增长、负 EBITDA、杠杆转负时崩溃 |

### 3g. 特定模型类型的常见缺陷

**DCF：**
- 折现率用错了期间（年中 vs 年末）
- 终值未折现回现值
- WACC 使用了账面价值而非市场价值
- FCF 中包含了利息费用（应为无杠杆）
- 税盾被重复计算

**LBO：**
- 债务偿还与现金扫除机制不符
- PIK 利息未计入本金滚存
- 管理层展期未反映在回报中
- 退出倍数用错了 EBITDA（LTM vs NTM）
- 费用未从第一天股权中扣除

**并购：**
- 增厚/摊薄使用了错误的股数（交易前 vs 交易后）
- 协同效应未分期实现
- 购买价格分摊不平衡
- 未计入现金的利息损失
- 交易费用未计入资金来源与运用

**三表模型：**
- 营运资本变动符号错误
- 折旧与 PP&E 明细表不一致
- 债务到期安排与本金偿付不符
- 股利超过净利润且无解释

## 第四步：报告

输出发现事项表格：

| # | 工作表 | 单元格/区域 | 严重性 | 类别 | 问题 | 建议修复方式 |
|---|---|---|---|---|---|---|

**严重性：**
- **严重** —— 输出错误（资产负债表不平、公式断裂、现金不勾稽）
- **警告** —— 存在风险（硬编码、公式不一致、边界情形失效）
- **提示** —— 风格/最佳实践（配色、版面、命名）

若为 **model** 范围，在最前面加一行摘要：

> 模型类型：[DCF/LBO/三表/…] —— 总体：[干净 / 轻微问题 / 重大问题] —— [N] 个严重、[N] 个警告、[N] 个提示

**未经询问不要修改任何内容** —— 先报告，按请求再修。

---

## 说明

- **先看资产负债表是否平衡** —— 如果不平，下游一切都值得怀疑
- **硬编码覆盖值是静默缺陷的头号来源** —— 要主动、彻底地搜索
- **符号约定错误**（现金流出用正还是负）极为常见
- 如果模型使用 VBA 宏，注明哪些由宏驱动的计算无法仅凭公式审计
